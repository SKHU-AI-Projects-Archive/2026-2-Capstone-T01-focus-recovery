# AI 파트 기능명세서

## 1. 문서 개요

본 문서는 사용자가 입력한 최초 작업 목표와 최근 웹 탐색 흐름을 분석하여 목표 이탈 상태를 분류하는 AI 파트의 기능을 정의한다. 페이지별 의미적 관련성, 탐색 맥락, 행동 특징을 결합하여 최근 탐색 구간을 `NORMAL`, `TRANSITION`, `DRIFT` 중 하나로 분류하는 것이 목적이다.

| 항목 | 내용 |
| --- | --- |
| 영역 | AI |
| 구성 기능 | AI-001, AI-002, AI-003 |
| 구현 상태 | 미착수 |
| 분석 기준 | 사용자가 입력한 최초 작업 목표 |
| 최종 판단 단위 | 최근 5개의 유효 Page Visit으로 구성된 탐색 구간 |
| 최종 출력 | 세 클래스의 예측 확률 및 최종 탐색 상태 |
| 연동 대상 | 백엔드의 AI 분석 요청·응답 처리 및 결과 저장 기능 |

### 1.1 기능 목록

| 기능 ID | 대분류 | 기능명 | 주요 역할 |
| --- | --- | --- | --- |
| AI-001 | 의미 분석 | 목표-페이지 의미적 관련성 계산 | 최초 목표와 각 페이지의 의미적 관련성을 계산한다. |
| AI-002 | 탐색 맥락 분석 | 최근 탐색 흐름 분석 | 최근 5개 방문의 순서와 주제 변화를 분석하여 맥락 특징을 생성한다. |
| AI-003 | 최종 분류 | 목표 이탈 분류 | 의미적·맥락적·행동 특징을 이용하여 최종 탐색 상태를 결정한다. |

### 1.2 적용 범위

AI 파트는 관련성 계산, 탐색 맥락 특징 생성, 최종 분류 결과 반환을 담당한다. 웹 탐색 정보 수집, 분석 요청 전달, 결과 저장, 목표 재제시 알림 표시는 연동 기능에서 담당한다.

세부 API 경로, 요청·응답의 전체 구조, 오류 코드 및 모델별 구현 방식은 별도 설계에서 확정한다.

## 2. 공통 분석 기준

### 2.1 용어 정의

| 용어 | 정의 |
| --- | --- |
| 최초 작업 목표 | 사용자가 작업 세션을 시작할 때 입력한 탐색 목적이다. |
| Page Visit | 세션 안에서 발생한 개별 페이지 방문 기록이다. |
| 유효 Page Visit | 분석 대상 조건을 충족하는 페이지 방문 기록이다. 구체적인 유효성 판정 기준은 수집·전처리 계약에서 확정한다. |
| 탐색 구간 | 최근 5개의 유효 Page Visit을 방문 순서대로 구성한 분석 단위이다. |
| 의미적 관련성 | 최초 목표와 개별 페이지 내용 사이의 의미적 관계를 표현하는 수치 특징이다. |
| 탐색 맥락 특징 | 최근 탐색 흐름의 목표 관련성, 우회의 합리성, 주제 이탈 정도 등을 표현하는 특징이다. |
| 행동 특징 | 활성 체류시간과 탭 전환 횟수 등 탐색 과정의 행동 정보이다. |

### 2.2 상태 정의

| 상태 | 의미 | 후속 시스템 동작 |
| --- | --- | --- |
| `NORMAL` | 최초 목표를 직접 수행하거나 목표 달성에 합리적으로 필요한 탐색 상태이다. | 목표 이탈 알림을 표시하지 않는다. |
| `TRANSITION` | 최초 목표와의 관련성이 감소하고 있으나 명확한 이탈로 판단하기 어려운 상태이다. | 추가 탐색을 관찰한다. |
| `DRIFT` | 최근 탐색 흐름이 최초 목표와 명확하게 관계없는 방향으로 지속적으로 이동한 상태이다. | 목표 재제시 알림 기능과 연계한다. |

`AI-002`의 `contextState`는 Context Model이 생성한 중간 맥락 판단이고, `AI-003`의 `result`는 최종 분류 결과이다. 두 값은 같은 상태 이름을 사용하더라도 동일한 결과로 취급하지 않는다.

### 2.3 분석 시점과 구간 구성

유효 Page Visit이 5개 이상 누적된 이후 새로운 유효 페이지 방문이 추가될 때마다 최근 5개 방문으로 분석 구간을 구성한다. 구간은 방문 1개씩 이동하는 sliding window 방식으로 갱신한다.

AI-001의 페이지별 관련성 계산은 유효한 목표와 분석 가능한 페이지 텍스트가 준비되면 수행할 수 있다. AI-002 및 AI-003의 구간 분석은 최근 5개의 유효 방문이 준비된 상태를 기준으로 한다.

### 2.4 전체 처리 흐름

1. 최초 작업 목표와 분석 대상 페이지의 제목 및 제한된 본문을 준비한다.
2. AI-001이 각 페이지의 의미적 관련성을 계산한다.
3. 최근 5개 방문의 관련성 통계와 변화량을 구성한다.
4. Context Model을 사용하는 구성에서는 AI-002가 탐색 맥락 특징을 생성하고 출력 형식을 검증한다.
5. AI-003이 선정된 구성에 필요한 의미적·맥락적·행동 특징으로 세 클래스의 예측 확률을 산출한다.
6. Validation 데이터에서 결정한 임계값을 적용하여 최종 상태를 반환한다.
7. 백엔드가 결과를 해당 탐색 구간과 연결하여 저장하고, 프론트엔드가 최종 결과에 따라 목표 재제시 기능을 수행한다.

### 2.5 공통 처리 원칙

- 단일 페이지의 관련성이 낮다는 이유만으로 목표 이탈을 확정하지 않는다.
- 페이지 텍스트나 필수 특징을 확보하지 못하면 임의의 관련성 값 또는 최종 상태를 생성하지 않는다.
- 분석 실패를 정상 분석 결과나 `NORMAL` 상태로 대신 반환하지 않는다.
- Context Model의 결과만으로 최종 상태 또는 알림 여부를 결정하지 않는다.
- 모델 종류, 특징 구성 및 DRIFT 임계값은 실제 검증 결과에 따라 결정한다.
- Test 데이터는 최종 모델과 설정이 확정된 이후 일반화 성능 평가에만 사용한다.

## 3. AI-001 목표-페이지 의미적 관련성 계산

### 3.1 기능 설명

선정된 Embedding Model을 이용하여 최초 작업 목표와 각 페이지의 제목 및 제한된 본문 사이의 의미적 관련성을 계산한다. 계산 결과는 최근 탐색 구간의 관련성 통계·변화량을 구성하고 후속 맥락 분석 및 최종 분류에 활용한다.

### 3.2 동작 조건

유효한 최초 작업 목표와 분석 가능한 페이지 제목 및 본문이 존재하는 경우 동작한다.

### 3.3 입력 데이터

| 항목 | 설명 |
| --- | --- |
| `goal` | 최초 작업 목표 |
| `title` | 분석 대상 페이지의 제목 |
| `content` | 분석 대상으로 제한된 페이지 본문 |

### 3.4 처리 절차

1. 최초 목표와 페이지 텍스트가 분석 가능한지 확인한다.
2. 선정된 Embedding Model로 최초 목표와 페이지 텍스트를 표현한다.
3. 최초 목표와 페이지 사이의 의미적 관련성을 계산한다.
4. 페이지별 `semanticRelevance`를 후속 분석에서 사용할 수 있는 형태로 반환한다.

### 3.5 출력 데이터

| 항목 | 설명 |
| --- | --- |
| `semanticRelevance` | 최초 목표와 해당 페이지의 의미적 관련성을 표현하는 수치 특징 |

관련성 계산식과 값의 범위는 모델 적용 설계에서 확정한다. AI-002의 `0.0~1.0` 범위를 이 값에 그대로 적용하지 않는다.

### 3.6 모델 선정 기준

| 구분 | 후보 및 적용 조건 |
| --- | --- |
| 1차 후보 | `Qwen3-Embedding-0.6B` |
| 대체 후보 | `multilingual-e5-base`, `BGE-M3` |
| 대체 검토 조건 | 1차 후보의 사용이 어렵거나 실제 검증 결과가 적합하지 않은 경우 |
| 최종 선정 | 실제 검증 결과에 따라 결정 |

### 3.7 예외 및 제한사항

페이지 텍스트를 정상적으로 확보하지 못하면 임의의 관련성 값을 생성하지 않는다. 단일 페이지의 결과는 수치 특징이며 최종 목표 이탈 상태를 의미하지 않는다.

### 3.8 완료 조건

- 최초 목표와 유효 페이지 내용에 대한 의미적 관련성을 계산할 수 있어야 한다.
- 최근 5개 방문의 관련성 평균 및 변화량 등 구간 특징을 생성할 수 있는 형태로 결과를 제공해야 한다.

## 4. AI-002 최근 탐색 흐름 분석

### 4.1 기능 설명

최근 5개의 유효 Page Visit을 하나의 탐색 흐름으로 보고 방문 순서와 주제 변화를 분석한다. 현재 탐색이 목표를 정상적으로 수행하는 과정인지, 합리적인 우회인지, 목표와 관계없는 방향으로 변화하는지 구조화된 특징으로 표현한다.

### 4.2 동작 조건

최근 5개의 유효 Page Visit으로 탐색 구간이 구성되고, Context Model을 사용하는 실험 또는 최종 시스템 구성인 경우 동작한다.

### 4.3 입력 데이터

| 항목 | 설명 |
| --- | --- |
| `goal` | 최초 작업 목표 |
| `visits` | 최근 5개의 유효 Page Visit |
| `searchQuery` | 탐색 과정에서 사용한 검색어 |
| `sequence` | 페이지 방문 순서 |
| `semanticRelevance` | AI-001에서 계산한 각 페이지의 목표 관련성 |

검색어를 확보하지 못한 방문의 표현 방식과 각 방문에 검색어를 연결하는 방식은 데이터 계약에서 확정한다.

### 4.4 처리 절차

1. 최초 목표, 최근 방문 기록, 검색어, 방문 순서, 페이지별 관련성을 Context Model에 전달한다.
2. Context Model이 탐색 맥락 특징을 구조화된 JSON으로 생성한다.
3. 출력 필드, 수치 범위 및 상태값이 명세에 맞는지 검증한다.
4. 검증에 성공하면 특징을 AI-003의 입력으로 제공한다.
5. 구조화된 출력 검증에 실패하면 1회 재시도한다.
6. 재시도에도 실패하면 해당 분석을 실패로 처리한다.

### 4.5 출력 데이터

| 항목 | 값의 범위 | 설명 |
| --- | --- | --- |
| `goalRelevance` | `0.0~1.0` | 최근 탐색 흐름이 최초 목표와 관련된 정도 |
| `detourJustification` | `0.0~1.0` | 현재 우회 탐색이 목표 달성에 합리적인 정도 |
| `driftDegree` | `0.0~1.0` | 다른 주제로 이동한 정도 |
| `contextState` | `NORMAL` / `TRANSITION` / `DRIFT` | Context Model의 중간 탐색 상태 판단 |

세 수치 특징은 각 정도를 표현하는 값이며, AI-003이 반환하는 클래스별 예측 확률과 구분한다.

### 4.6 출력 검증 기준

- 출력은 파싱 가능한 JSON이어야 한다.
- 명세에 정의된 네 출력 항목을 확인할 수 있어야 한다.
- 세 수치 특징은 `0.0~1.0` 범위의 유효한 수치여야 한다.
- `contextState`는 정의된 세 상태 중 하나여야 한다.
- 검증에 실패한 출력을 후속 분류에 정상 특징으로 전달하지 않아야 한다.

### 4.7 모델 선정 기준

| 구분 | 후보 및 적용 조건 |
| --- | --- |
| 1차 후보 | `Qwen3-4B` |
| 비교 후보 | `Qwen3-8B 4-bit` |
| 비교 데이터 | Validation 데이터 |
| 선택 기준 | 성능 차이가 크지 않으면 응답시간과 자원 사용량이 낮은 모델 선택 |
| 제거 조건 | Context Model이 최종 성능 향상에 기여하지 않는 경우 |

Context Model을 제거한 최종 구성이 선정되면 AI-002는 수행하지 않고, AI-003은 Context 관련 특징을 사용하지 않는다. 이는 검증을 통해 선정하는 시스템 구성이다. Context 분석 실패 시의 즉시 대체 처리로 정의하지 않는다.

### 4.8 예외 및 제한사항

구조화된 출력 검증 실패에 대한 재시도는 1회로 제한한다. 재실패한 분석에서는 목표 재제시 알림을 발생시키지 않는다. `contextState`를 최종 분류 결과로 대신 사용하지 않는다.

### 4.9 완료 조건

- 최근 5개 방문을 기반으로 구조화된 탐색 맥락 특징을 반환할 수 있어야 한다.
- 모든 출력에 형식과 값 검증을 수행해야 한다.
- 검증 실패 시 1회 재시도하고 재실패를 정상 결과로 처리하지 않아야 한다.

## 5. AI-003 목표 이탈 분류

### 5.1 기능 설명

최근 5개 방문으로 구성된 탐색 구간의 의미적 관련성, 최근 관련성 변화, 탐색 맥락 및 행동 특징을 이용하여 최종 탐색 상태를 분류한다.

### 5.2 동작 조건

분석 대상 탐색 구간에 대해 선정된 분류기와 특징 구성에서 요구하는 입력 특징이 준비된 경우 동작한다.

### 5.3 입력 특징

| 특징 | 설명 | 적용 조건 |
| --- | --- | --- |
| 의미적 관련성 | 각 페이지와 최초 목표의 `semanticRelevance` | 공통 |
| 최근 관련성 통계 | 최근 5개 페이지의 관련성 평균, 변화량 등 | 공통 |
| `goalRelevance` | 탐색 흐름의 목표 관련성 | Context 사용 구성 |
| `detourJustification` | 합리적 우회 탐색 정도 | Context 사용 구성 |
| `driftDegree` | 다른 주제로 이동한 정도 | Context 사용 구성 |
| 활성 체류시간 | 분석 구간의 행동 특징 | 행동 특징 사용 구성 |
| 탭 전환 횟수 | 분석 구간의 행동 특징 | 행동 특징 사용 구성 |

Context Model을 제거한 최종 구성이 선정된 경우 Context 관련 특징은 사용하지 않는다. 관련성 통계·변화량의 계산식과 행동 특징의 구간 집계 방식은 특징 설계에서 확정한다. `contextState`의 분류기 입력 사용 여부와 인코딩 방식은 별도 확정 사항이다.

### 5.4 처리 절차

1. 선정된 특징 구성에 필요한 입력이 준비되었는지 확인한다.
2. 의미적·맥락적·행동 특징을 분류기 입력으로 구성한다.
3. 선정된 DriftClassifier가 `P(NORMAL)`, `P(TRANSITION)`, `P(DRIFT)`를 산출한다.
4. Validation 데이터에서 결정한 DRIFT 임계값 `τ`를 적용한다.
5. 세 클래스의 예측 확률과 최종 상태를 반환한다.

### 5.5 최종 상태 결정 규칙

| 조건 | 최종 상태 |
| --- | --- |
| `P(DRIFT) >= τ` | `DRIFT` |
| `P(DRIFT) < τ`이고 `P(NORMAL) > P(TRANSITION)` | `NORMAL` |
| `P(DRIFT) < τ`이고 `P(TRANSITION) > P(NORMAL)` | `TRANSITION` |

`P(DRIFT) < τ`인 경우에는 `P(NORMAL)`과 `P(TRANSITION)` 중 높은 상태를 선택한다. 두 확률이 같은 경우의 처리 규칙은 구현 전 확정한다.

`τ`는 Validation 데이터에서 결정하고 Test 결과를 이용하여 다시 조정하지 않는다.

### 5.6 출력 데이터

| 항목 | 설명 |
| --- | --- |
| `pNormal` | `NORMAL` 예측 확률 |
| `pTransition` | `TRANSITION` 예측 확률 |
| `pDrift` | `DRIFT` 예측 확률 |
| `result` | `NORMAL` / `TRANSITION` / `DRIFT` 중 최종 상태 |

백엔드가 최종 결과를 분석 대상 탐색 구간과 연결하여 저장할 수 있어야 한다. 구간 식별자의 필드명과 전달 방식은 BE·AI 연동 계약에서 확정한다.

### 5.7 분류기 선정 기준

| 항목 | 내용 |
| --- | --- |
| 비교 후보 | `Logistic Regression`, `Random Forest`, `XGBoost` |
| 선정 데이터 | Validation 데이터 |
| 성능 지표 | Macro F1, 클래스별 F1, DRIFT Recall, 오알림률 |
| 추가 비교 항목 | Train-Validation 성능 차이, 추론시간 |
| 최종 선정 방식 | 위 지표를 종합하여 분류기 선정 |
| 최종 평가 | 모델 및 설정 확정 후 Test 데이터로 일반화 성능 평가 |

### 5.8 예외 및 제한사항

단일 페이지의 관련성이 낮다는 이유만으로 `DRIFT`로 분류하지 않는다. 선정된 구성의 필수 특징을 정상적으로 생성할 수 없으면 임의의 상태를 반환하지 않는다.

Test 데이터는 모델 선택, 파라미터 조정 또는 임계값 결정에 사용하지 않는다.

### 5.9 완료 조건

- 분석 구간에 대해 세 클래스의 예측 확률과 최종 상태를 반환할 수 있어야 한다.
- Validation 데이터에서 결정한 기준으로 `DRIFT`를 판정해야 한다.
- Context 사용 여부에 따라 선정된 특징 구성을 적용해야 한다.
- 백엔드가 최종 결과를 해당 탐색 구간과 연결하여 저장할 수 있어야 한다.

## 6. 예외 처리 및 실패 전파

| 상황 | 처리 기준 | 후속 처리 |
| --- | --- | --- |
| 페이지 텍스트 확보 실패 | 임의의 `semanticRelevance`를 생성하지 않음 | 유효 구간과 필수 특징을 구성할 수 없으면 최종 분류를 수행하지 않음 |
| 최근 유효 방문 5개 미충족 | 구간 분석 동작 조건 미충족 | 구간이 준비된 이후 분석 |
| Context 출력 검증 실패 | 1회 재시도 | 재시도 성공 시 후속 분류 |
| Context 출력 재검증 실패 | 해당 분석 실패 | 최종 상태로 대체하지 않고 목표 재제시 알림을 발생시키지 않음 |
| 최종 분류 필수 특징 생성 실패 | 임의의 상태를 반환하지 않음 | 분석 실패를 정상 결과로 저장하거나 표시하지 않음 |
| Context 제거 구성이 선정됨 | Context 특징을 사용하지 않음 | 선정된 특징 구성으로 최종 분류 |

분석 실패를 전달하는 응답 구조와 오류 코드는 BE·AI 연동 설계에서 확정한다. 재시도 1회 규칙은 Context의 구조화 출력 검증 실패에 적용하며, 다른 오류에 대한 재시도 정책은 별도 확정한다.
